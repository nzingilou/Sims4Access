# Unbound focused UI right-click

Add A11yRightClick to the existing native UI-message listeners, with three isolated TooltipManager methods: A11yRightClickOwner, A11yTryRightClick and A11yMsgRightClick. No key binding or automatic invocation is added. A future binding can use tyjokr_a11y_keys._send('A11yRightClick'); the action now uses the same input-epoch fence as Enter/Toggle. Startup navigation remains unsupported for this live-UI action.

The handler requires the UI Cheats-only GenericCheatsExtension class (absent from all 258 scanned native movies), an already attached compatible extension, live owned focus, current keyboard lease, no text editing or pending navigation, native enabled/mouse-enabled state, and a valid on-stage hit point. GetExtension(Class,false) never creates an extension. Need bars use the existing extension's mcProgressBar and native ID. One non-bubbling MouseEventEx CLICK, marked RIGHT_BUTTON, is sent to the native listener owner at the correct local coordinates; no down/up/left fallback is sent. Currency and milestone Setup-based extensions use the nearest existing click-listener child within the extension owner; dispatch does not bubble to a broader category/panel. Native UI Cheats handles its own dialog or action. No cheat commands, confirmation buttons or game values are invoked directly by this adapter.

Native evidence: UI Cheats 1.59.1 Generic/ProgressBar/Buff/Goal and other extensions listen to MouseEvent.CLICK and InputUtils.IsRightMouseButton; ProgressBarCheatExtension also hit-tests stage coordinates. Native ExtendableComponent.GetExtension takes a second create-if-missing flag. The click stays on one owner to avoid double delivery through bar and container listeners. Existing UI Cheats actions can themselves act immediately (for example buff removal); this adapter preserves that behavior after an explicit request.

Logs: right-click|sent records the native owner class and delivered stage coordinates; right-click|blocked records refusal. No shortcut is assigned yet. This targets focused UI controls, not world/scanner objects. Standard-game operation without the UI Cheats class refuses safely. Live-game confirmation of delivered events is pending.

Tests: tools/test_ui_rightclick.js (30 native-shaped fixtures); tools/test_ui_rightclick_queue.py (three queued-input cases). Compiled UI gates and the cumulative package validation are recorded separately.
