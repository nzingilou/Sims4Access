# Doctor patient reader

Add Scripts/tyjokr_a11y_doctor.py and one hub row/command (a11y.patients). Native pickers list current hospital patients, visit stage, discovered symptoms/diagnosis, recorded examinations, attempted treatments and ruled-out treatments. Each callback revalidates zone, active working Sim/career and current PatientSituationBase membership. Native localized labels are passed to the client; internal tuning names never become clinical narration. Patient interactions reuse the existing native pick message and choose no action.

Current symptom activity reads only running SI/queue interactions matching the EP01 idle_Buff_SickessSystem_Symptom_* names found in installed tuning. Queued work and illness-associated symptom lists are excluded. This is an observation of a mapped animation, separate from a discovered examination finding. Unmapped activity and skin patterns are not inferred. Explicit per-patient presentation logging records active buff/effect metadata for further mapping. The existing careerlog research hooks are unchanged; there are no new runtime patches or background polling.

Native evidence inspected: sickness_tracker.pyc properties and discovery methods; sickness.pyc threshold actions; symptom.pyc localized display-name contract; PatientSituationBase; interaction.get_name and running properties; SIState/InteractionQueue iteration. EP01 SimulationFullBuild0 combined tuning contains the named symptom-animation resources. The hidden current_sickness property is read only after has_discovered_sickness is exactly True. No diagnosis statistic, correct treatment list or mutation API is used.

Validation: tools/test_doctor.py covers hidden-answer traps, native labels, stale menus, missing APIs/patients, current-vs-queued activity, diagnostic opt-in and native pick routing. First hospital workday testing is pending; use Accessibility menu > Doctor patients and refresh after examinations. No new UI package behavior or keyboard shortcut is required.
