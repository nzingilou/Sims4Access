# Native water tools and Shift+Enter

- Add tyjokr_a11y_water_tools.py, a separate experimental square/rectangular pool assistant under Alt+B. Uses EA ProductTypes.BLOCK (16) with BUILDTAG_BLOCK_POOL_TOOL, confirms one native catalogue tool and its serial-scoped selection reply, then uses the existing measured mouse-drag path. Never edits terrain, funds or native pool data directly.
- Ground-floor flat natural ground only, 2–20 metres per side, a one-metre lot inset, no existing/adjacent pool and conservative furniture/landscaping clearance. Rechecks context/site after camera preparation. Success requires all intended tiles to become pool, unchanged border and unchanged building geometry; no automatic retry or undo. Construction is off by default, persisted as [build cursor] pool construction and exposed in accessibility settings.
- Read-only catalogue diagnostics cover pool presets, fountain tools/presets, ponds and terrain sculpting. Logging must be enabled first. Fountain decorations/emitters use existing object placement. Curved-pool assembly, fountain basins and terrain reshaping remain research.
- plus_build.py explicitly dispatches selection replies to the observer and adds one menu row; no runtime monkey-patching.
- Bind Shift+Enter only to focused supported UI controls in Live mode, preserving text fields, ordinary Enter, scanner and Build placement. Native guard consumes the physical key; Python sends one epoch-fenced A11yRightClick request. Restore November 15 native UI refinements on the new upstream source.
